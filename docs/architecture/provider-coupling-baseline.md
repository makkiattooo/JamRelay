# Provider Coupling Baseline

Status: baseline only; no provider abstraction is introduced by this document.

## Audit context

- Audited snapshot: `33e797ea6f29ae47284434ddbfde7dd4c9956d5f`
- Package version: `1.1.0`
- Runtime shape: TypeScript/Node 22 ESM, Express, MCP Server v2, Zod, `node:sqlite`, Pino and Vitest.
- Existing `HEAD` matches the audited snapshot and the working tree was clean before this document was added.
- `node_modules` was already present, so `npm ci` was not required.

The current implementation is intentionally Spotify-specific. Spotify behavior is the production/reference behavior and must remain unchanged while later phases introduce provider-neutral seams.

## Configuration, schema and endpoint markers

- `SPOTIFY_*` variables occur in `src/config.ts`, `src/index.ts`, `.env.example`, the README, tests, and generated/source environment documentation. The complete runtime set is `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REDIRECT_URI`, `SPOTIFY_TOKEN_STORE_PATH`, and `SPOTIFY_MARKET`.
- Spotify-named schema columns include `tracks.spotify_track_id`, `tracks.spotify_uri`, `playlist_snapshots.spotify_snapshot_id`, and `listening_events.spotify_track_id`; source values and aliases also include `spotify_search` and `spotify_response`.
- Hard-coded provider URLs are confined to `src/spotify/auth.ts`, `src/spotify/client.ts`, and Spotify identifier parsing in `src/spotify/identifiers.ts`. Outside that directory, `src/db/state.ts` uses `https://spotify.invalid` only as a URL parsing base, and tests/docs contain representative Spotify identifiers and URLs.
- Explicitly Spotify-specific MCP descriptions/results are in `src/mcp/tools.ts` and `src/mcp/helpers.ts`: catalog and playback descriptions, `external_url` values sourced from Spotify, `spotify_status`, `spotify_snapshot_id`, `spotify_feature_removed`, `removed_by_spotify`, and Spotify-specific limitation/error text. Existing tool names and result shapes are compatibility contracts for this phase.

## OAuth boundary and safety rules

JamRelay MCP OAuth is implemented in `src/mcp/oauth.ts` and uses `MCP_OAUTH_*` configuration plus its own store (`MCP_OAUTH_STORE_PATH`). It authenticates the MCP client to JamRelay. Music-provider OAuth is implemented in `src/spotify/auth.ts`, uses Spotify client credentials and redirect configuration, and stores encrypted provider tokens through `src/spotify/token-store.ts`. These flows, credentials and stores must not be merged.

Provider credentials must never be stored in plaintext. Provider writes must never silently fall back to another provider. The existing MCP surface, snapshot/rollback/undo/dry-run semantics and Spotify behavior remain unchanged until a later phase explicitly changes them.
